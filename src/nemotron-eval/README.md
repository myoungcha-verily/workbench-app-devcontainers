# Nemotron Eval Terminal

Chat, agent and canvas UI for self-hosted NVIDIA Nemotron models in Verily Workbench. Models run locally in
Ollama on the app's GPU. The agent can use Workbench (through the Workbench MCP server), query BigQuery,
and build artifacts — reports, SQL, charts and HTML mini-apps — in a side canvas.

## Features

- **Workbench agent**
  - Workspace context generated by `llm-context` (your buckets, datasets, workflows, skills).
  - All Workbench MCP tools: a core set is always loaded, and the model enables the rest with `find_tools`.
  - Local tools: `run_sql`, `list_tables`, `describe_table` (columns, descriptions, value hints), skills and artifacts.
  - **Deletes ask for approval.** Delete/remove/revoke tools, and `rm`/`delete`/`DROP`/`DELETE FROM` inside
    `bq`, `gsutil`, `gcloud` and `wb` commands, show **Approve / Deny** in the chat.
- **Reasoning and effort**
  - Reasoning off/on, or levels where the model supports them (read from Ollama).
  - Effort presets: quick / balanced / thorough set the output budget and tool-step limit.
  - Mode presets: Workbench agent, Data analyst, SQL expert, Plain chat.
  - Per-chat custom instructions, temperature and max tokens.
- **Canvas**
  - Markdown documents.
  - SQL with **Run**, a results table, CSV download and one-click charts.
  - Vega-Lite and Plotly charts.
  - Sandboxed HTML/JS mini-apps that can run live SELECT queries through `await workbench.query(sql)`.
  - Code and CSV.
  - Every artifact is versioned (restore earlier versions), editable, downloadable and can be saved to a bucket.
- **Quality of life**
  - Markdown with syntax highlighting, and live tokens/s and context-usage meters.
  - Stop, regenerate, edit and resend, copy.
  - Chats are searchable, renameable, exportable to Markdown and can be saved to a bucket.
  - Prompt library, file attachments (drag and drop), slash commands (`/ls`, `/tables`, `/schema`, `/sql`, `/tools`, …).
  - Compare mode (one prompt, several models).
  - Data notes shared by every chat.
  - Light/dark theme, keyboard shortcuts, browser notifications.
- **Eval tab:** quick smoke tests over `tasks/benchmark_tasks.json`.

## Design choices backed by eval-bench

The prompt and tools are shaped by failure analysis of Nemotron 3.5 Lightning and Ultra in
`~/eval-bench` (model-only Baseline track; the agent track was used for behaviour only):

| Observed failure (Lightning unless noted) | Countermeasure |
|---|---|
| 134+ agent queries broken by shell-mangled backticks | SQL only via `run_sql` (JSON argument); `bq_execute` is not a core tool |
| Hallucinated columns (33 model-only, 58 agent) | `describe_table` before querying; errors list the real columns |
| `project.Table` paths missing the dataset (18) | Errors suggest the full `project.dataset.table` |
| Same failing query re-run up to 25× | Loop guard refuses identical failed calls; nudge after 3 errors in a row |
| Answers cut off by the output limit | 16K (balanced) / 32K (thorough) output budget per step |
| Wrong categories, units and 0/1 flags; trusting planted doc errors | Value hints, "verify against the data" rules, BigQuery dialect cheat sheet |
| Data dictionary: +27 points (34% → 61%) | **Settings → Data notes** goes into every system prompt |

## Models

| Model ID | Source | Min VRAM |
|---|---|---|
| `nemotron-3-nano:4b` | Ollama registry (GCS GGUF fallback) | 6 GB |
| `nemotron-nano:9b-v2` | `gs://$MODELS_BUCKET/models/…9B-v2-Q4_K_M.gguf` | 10 GB |
| `nemotron-3.5-bolt:74b` | `gs://$MODELS_BUCKET/models/…Bolt-74B-A9B-24GB.gguf` | 24 GB |

Models that fit the GPU are prepared in the background on first start. Weights are cached on the data
volume, and the largest model is pre-loaded so the first chat is fast. Only one model fits in VRAM at a
time on an A100 40GB, so switching models takes about a minute; the chat says so while it happens.

## Deploy

1. Create a custom app config pointing at this folder:
   ```bash
   wb app config create --name=nemotron-eval-terminal \
     --git-repo-url=https://github.com/<you>/workbench-app-devcontainers.git \
     --git-branch=<branch> --dev-container-path=src/nemotron-eval
   ```
2. Create the app on a GPU: `a2-highgpu-1g` (A100 40GB) for all three models, or a T4 for the 4B and 9B.
3. Open the app, or go to `https://workbench.verily.com/app/<APP_UUID>/proxy/8080/`.

Settings live in `docker-compose.yaml` (`ENABLED_MODELS`, `MODELS_BUCKET`, `RESULTS_BUCKET`,
`OLLAMA_CONTEXT_LENGTH`).

## Layout

```
.devcontainer.json        features (workbench-tools, wb-mcp-server, llm-context) + lifecycle hooks
docker-compose.yaml       application-server on app-network, home + data volumes
Dockerfile                python:3.11-slim + pinned Ollama, user `nemotron`
scripts/                  entrypoint (Ollama + uvicorn), start-services (MCP server + context)
backend/
  main.py                 REST + WebSocket API, static frontend
  agent.py                agent loop: streaming, tool calls, approvals, loop guard, budgets
  tools.py                tool catalog, core set, delete detection
  catalog.py              workspace datasets/buckets, list/describe tables, SQL error hints
  context.py              system prompts, presets, workspace context, skills, data notes
  mcp_client.py           Workbench MCP client
  sqlrun.py               BigQuery execution (dry-run checks, read-only mode for mini-apps)
  model_manager.py        model download/import, capabilities, warm-up
  store.py                DuckDB: chats, artifacts (versioned), prompts, eval runs
frontend/                 no build step; ES modules + vendored libraries (vendor/SHA256SUMS)
```

## Troubleshooting

| Symptom | Check |
|---|---|
| Status shows `tools …` | MCP server not up yet: `docker exec application-server pgrep -af wb-mcp-server`; logs in `/tmp/wb-mcp-server.log` |
| Status shows `context …` | Context generation runs after Workbench login; log in `/tmp/llm-context.log` |
| A model is stuck in `loading` | `docker logs application-server` (the `[models]` lines) |
| "error launching your custom container" | On the VM: `sudo journalctl -u devcontainer.service` |
